# Issues

Отложенные улучшения из `/simplify` по переносу «боулдеринг с любым числом трасс» (веб-коммит `fb0a143`).

## Объединить `BoulderQualItem` и `BoulderFinalItem`

`src/shared/types/groups.ts` — после замены `r1..rN` на индексную сигнатуру `` [route: `r${number}`]: string `` оба интерфейса совпадают поле в поле. Оставить один `BoulderItem` (второй — алиас или удалить). В вебе типы тоже раздельные — делать в обоих репозиториях.

## Заглушка `ROUTES_PROP` совпадает с реальным ключом данных

`src/shared/tables.configs.ts` — `ROUTES_PROP = 'r1'` и фиктивное `name: '1'` в `boulderQualConfig`/`boulderFinalConfig`. Если конфиг прочитать без `withRouteColumns`, тихо покажется только трасса 1. Переименовать в значение, которое не может быть ключом данных (например, `'routes'`), и убрать неиспользуемое `name`. Ради паритета — синхронно с вебом.

## Встроить `withRouteColumns` в `getTableConfig`

`src/components/tables/Table.tsx` — вызывающий сам собирает цепочку `getTableConfig` → `withRouteColumns` → фильтр по ключам первой строки. Вариант: `getTableConfig({ ..., firstResult })` возвращает готовый список колонок (заодно не сканирует ключи для трудности/скорости, где трасс нет). В вебе та же трёхшаговая цепочка — делать в обоих репозиториях.
